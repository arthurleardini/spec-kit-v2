Spec Kit v2

Kit replicável de skills para escrever a spec de um produto como wiki wikiLLM: o agente escreve e mantém o markdown, o humano cura as fontes e pergunta.

25 min · 4 blocos formato: walkthrough público: 2-6
1

O que é + problema que resolve

5 min2-3

O que é

Um kit de skills (roda no Cursor) que constrói a especificação de um produto em duas camadas, mais uma camada transversal compartilhada:

  • Camada de Intenção (visao.md): por que e para quem o produto existe. Um doc, três capítulos: Produto, Glossário, Regras & Métricas.
  • Camada de Requisitos (Requisitos/<feature>.md): o que o produto faz, feature a feature. Um doc por feature, três capítulos: Telas & Fluxos, Requisitos & Cenários, Dados.
  • Transversais (modelo-dados.md, telas-comuns.md, requisitos-transversais.md): o que vale para várias features mora aqui uma vez; a feature referencia.

Problema que resolve

Spec espalhada, requisito repetido em cada feature, telas se multiplicando. A v2 ataca isso com três decisões de design:

  • Transversal-first: modelo de dados, telas e RNF/RF comuns são definidos uma vez; a feature aponta para eles e descreve só o próprio.
  • Minimizar telas: reusar arquétipos de telas-comuns.md e fundir vistas em abas/drawers em vez de criar tela nova.
  • Agentes especialistas, saída enxuta: cada skill cuida de um capítulo e gera menos artefato, com linguagem de produto agnóstica de tecnologia.

Caso prático

12 min4-6

Abrir a árvore refined/ de um projeto real (ou do template) e navegar no refined-navigator.html, com Mermaid renderizado e wireframes fat-marker.

# refined/ · o wiki de um produto refined/ ├─ visao.md Intenção: Produto · Glossário · Regras & Métricas ├─ blueprint.md cadeia de valor (product-level) ├─ modelo-dados.md ┐ ├─ telas-comuns.md ├ transversais (definidos 1x) ├─ requisitos-transversais.md ┘ RNF-T-* / RF-T- * / Integrações ├─ Requisitos/ │ ├─ feature-a.md Telas&Fluxos · Requisitos · Dados │ └─ feature-b.md └─ refined-navigator.html artefato navegável

O detalhe que ancora tudo: o eixo no frontmatter

Cada contrato declara eixo: processo ou eixo: classe. É a mesma camada de Requisitos, parametrizada pela granularidade.

eixo: processo

Atividade / fluxo

A 1.1 funde fluxo e processo num flowchart (BPMN leve). Os dados do Cap.3 derivam das atividades. Bom para jornadas e tramitação.

eixo: classe

Formulário / objeto

A 1.1 é o ciclo do formulário. A própria classe já é o modelo de dados do Cap.3. Bom para cadastros e objetos.

Ressalva (fora do kit): a ponte do eixo com BPMN (Especificator) e FormDef (Prototipator) é integração SYDLE, não faz parte do spec-kit-v2 hoje. Nenhuma skill referencia essas ferramentas. Ver bloco 4 (BL-16).

Para fechar a demo: os dois artefatos HTML abrem com duplo-clique, sem servidor. refined-navigator.html navega o wiki; blueprint.html mostra a cadeia de valor.
